# Plan

Planning is read-only. Do not edit project files, branches, commits, or external systems.

1. Establish the outcome, scope, constraints, authority, and success criteria.
2. Inspect high-signal evidence: repository instructions, status and diff, entry points, tests, configuration, docs, and relevant history.
3. Explain the current state and the smallest coherent gap to the target.
4. Resolve uncertainty with focused read-only checks. Ask only when a missing decision would materially change behavior, cost, risk, or authority.
5. Give the fewest ordered steps that make execution unambiguous. Include affected areas, dependencies, risks, verification, cleanup, and recovery when relevant.
6. Review once for omissions, needless ceremony, speculative scope, and steps that cannot be executed from the evidence.

Use a short plan for ordinary material work. Create plan files, parallel workstreams, or broad matrices only when the work is long, risky, interruptible, or genuinely separable.
