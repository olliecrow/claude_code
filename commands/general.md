# General task

Establish the intended outcome, purpose, constraints, authority, and proof of completion. Read the repository instructions and inspect the current status before acting.

- For an explanation, diagnosis, review, or status request, stay read-only.
- For an implementation request, fix the root cause with the smallest coherent change.
- Preserve unrelated and concurrent work.
- Use a short plan only when the work is material.
- Keep one implementation owner. Delegate only bounded work that is genuinely separable.
- Prefer direct names, obvious control flow, existing primitives, and one current path.
- Do not add speculative options, fallbacks, abstractions, dependencies, docs, or compatibility layers.
- Verify in proportion to risk and run every required repository gate.
- Remove temporary, stale, duplicate, and superseded artifacts within scope.

Lead the final response with the outcome. Include only important decisions, evidence, checks, and remaining gaps.
